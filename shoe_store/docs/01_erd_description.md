ОПИСАНИЕ ER-ДИАГРАММЫ

Описание ER-диаграммы которую я сделал в draw.io. В диаграмме семь таблиц. Ниже назначение каждой таблицы, её ключи и связи между таблицами.

Таблицы
roles
Назначение: справочник ролей. Тут хранятся названия ролей пользователей. Отдельная таблица нужна, чтобы название роли не дублировалось у каждого пользователя.

Ключи: role_id - первичный ключ (PK)

Поля: role_id, role_name


users
Назначение: хранит пользователей системы. По логину делается вход. Пароль не нужен.

Ключи:

user_id - первичный ключ (PK)

role_id - внешний ключ (FK) на roles.role_id

Поля: user_id, last_name, first_name, middle_name, login, role_id


products
Назначение: хранит товары. То есть модели обуви.

Ключи: product_id - первичный ключ (PK)

Поля: product_id, category, subcategory, producer, name, image_path, composition, description, price


sizes
Назначение: справочник размеров. Тут хранятся числа вроде 36, 37, 38. Отдельная таблица нужна, чтобы не писать размер текстом в каждом товаре.

Ключи: size_id - первичный ключ (PK)

Поля: size_id, value

stock_items
Назначение: товарные позиции. Тут хранится количество для каждой комбинации модели и размера. Это и есть та самая товарная позиция из описания предметной области.

Ключи:

stock_item_id - первичный ключ (PK)

product_id - внешний ключ (FK) на products.product_id

size_id - внешний ключ (FK) на sizes.size_id

Поля: stock_item_id, product_id, size_id, quantity_available


orders
Назначение: хранит заказы.

Ключи:

order_id - первичный ключ (PK)

user_id - внешний ключ (FK) на users.user_id

Поля: order_id, order_date, user_id

Итоговая сумма не хранится. Она вычисляется при выборке.


order_items
Назначение: состав заказа. Тут хранятся позиции внутри заказа.

Ключи:

order_item_id - первичный ключ (PK)

order_id - внешний ключ (FK) на orders.order_id

stock_item_id - внешний ключ (FK) на stock_items.stock_item_id

Поля: order_item_id, order_id, stock_item_id, quantity, price_at_order

Цена хранится прямо тут. Это нужно, потому что цена товара может поменяться в будущем. А в заказе должна остаться та цена, по которой товар был куплен.

Связи:

Связь	                   Тип	            Что значит
roles - users	           1:N	 Одна роль у многих пользователей
users - orders	           1:N	 Один пользователь делает много заказов
orders - order_items       1:N	 В одном заказе много позиций
products - stock_items     1:N	 У одного товара много товарных позиций
sizes - stock_items	       1:N	 Один размер у многих товарных позиций
stock_items - order_items  1:N	 Одна товарная позиция может быть во многих заказах
